# فريق الوكلاء المحلي — BuildTrack

## الغرض وحدود الصلاحية

هذا الفريق المحلي يسرّع التحليل والمراجعة أثناء توفر Codex أو عدم توفره، لكن لا
يملك أي صلاحية لاعتماد تصميم أو تعديل ملفات التطبيق أو قاعدة البيانات. **Codex هو
مدير المنتج والتكامل والمراجع النهائي.** لا يدمج Codex أي اقتراح إلا بعد مراجعة
الدليل واختبارات القبول والبناء.

لا توجد آلية موثقة تجعل Codex المدفوع يتحول تلقائياً إلى Ollama عند انتهاء حد
الاستخدام. المسار البديل هنا مستقل: Ollama ينتج تقارير مراجعة محلية محفوظة، ثم
يراجعها Codex عند عودته. هذا يمنع تنفيذ كود غير مختبر في غياب المراجع النهائي.

## الفريق والتوزيع

| الدور | النموذج | العمل المسموح | ممنوع |
|---|---|---|---|
| قائد المنتج والتكامل | Codex | يحدد الأولوية، معايير القبول، يراجع التقارير، يحرر الكود، يختبر ويعتمد | اعتماد رقم أو تغيير بلا دليل |
| مخطط التنفيذ المحلي | `qwen2.5-coder:7b` | قراءة ملفات المهمة، كشف نقاط الدمج، اقتراح خطوات واختبارات | تعديل أي ملف أو migration أو بيانات |
| مراجع الحوكمة المستقل | `llama3.1:8b` | تحدي الافتراضات، العلاقات، الحوكمة، الحسابات، وحالات الفشل | تعديل أي ملف أو اعتماد النتيجة |
| مساعدة كتابة | `qwen2.5-coder:1.5b-base` | إكمال محلي داخل Continue | قرارات التصميم أو التشغيل الذاتي |
| فهرسة المشروع | `nomic-embed-text` | استرجاع سياق المشروع في Continue | توليد أو تعديل محتوى |

## حد الموارد

- لا يعمل نموذجان كبيران معاً. مشغل الفريق يستدعيهما بالتتابع فقط.
- `keepAlive: 0` في Continue؛ النموذج يفرغ من الذاكرة بعد المهمة.
- حد السياق 4096 للنموذجين 7B/8B. أي تحليل أكبر يقسم إلى وحدات ملفات صغيرة.
- لم يتم اختيار Mistral Nemo 12B أو DeepSeek 16B: قد يقتربان من/يتجاوزان هامش
  7–8GB المطلوب على RAM 16GB مع تشغيل التطبيق.

## طريقة التشغيل

المهمة النشطة محفوظة في [ACTIVE.md](agent-work-orders/ACTIVE.md). للتقرير المحلي
فقط، شغّل من جذر المشروع:

```powershell
./tools/run-local-agent-team.ps1 -Feature 'C2 Baseline comparison' -ReviewFile 'src/data/baselineGovernance.ts','src/App.tsx','tests/phase0-governance.test.mjs'
```

التقارير تحفظ في `tmp/ollama-reviews/` ولا تدخل في Git. إذا انتهى حد Codex، يمكن
لهذا الأمر أن يستمر كفحص محلي فقط. عند عودة Codex، يقرأ التقرير، يرفض أي افتراض
غير مثبت، ثم ينفذ التغيير في increment مستقل مع اختبارات.

## معيار كل ميزة

1. توجد بطاقة عمل محددة ومعايير قبول موجبة وسالبة ومصادر بيانات واضحة.
2. يراجع Qwen وLlama الملفات المحددة فقط؛ التقرير ليس دليلاً كافياً وحده.
3. يدمج Codex increment واحداً فقط.
4. تمر الاختبارات المرتبطة، `npm test`، `npm run build`، وفحوص Rust المناسبة.
5. تشغل مراجعة Ollama النهائية وتحفظ نتيجتها.
6. لا توسم الميزة مكتملة إلا إذا حققت 8/10 أمام الوظيفة المكافئة في SAP PS.
