# بطاقة عمل تصحيحية للوكلاء المحليين

## C2.1R — Forecast fields in the activity variance register

## الهدف التشغيلي

إكمال سجل فرق النشاط ليعرض Baseline وCurrent وCPM Forecast بصورة منفصلة، دون
تعديل بيانات الخطة أو الـBaseline، وبمنطق قابل للتدقيق لمدير المشروع.

## مصدر الحقيقة والحدود غير القابلة للتعديل

- `BaselineActivitySnapshot` حقيقة تاريخية مجمدة، وحقول النشاط الحية هي Current.
- Forecast موجود فقط في `forecast_start_date` و`forecast_end_date`; عند غيابهما
  يجب عرض null/Unavailable، لا اشتقاق موعد أو مدة مخترعة.
- `activity_code` و`predecessor_links`/`stableJson` منطق قائم لا يجوز حذفه.

## معايير القبول

1. الـpatch يعدل `BaselineActivityVariance` و`compareBaselineActivityDetails`
   فقط داخل الملف المستهدف ليضيف حقول Forecast الصريحة وفرقها عن Baseline.
2. يضيف `Forecast` إلى `changedFields` فقط عندما توجد بيانات CPM فعلية وتختلف
   عن Baseline؛ غياب forecast ليس تغيرًا في Current Plan.
3. يظل `Critical` و`predecessor` ومنطق Baseline/Current الحاليان موجودين دون
   ازدواج أو تعديل للخطة.
4. في patch نفسه تظهر حالة اختبار مقترحة لتوقع متأخر وحالة forecast غائب.

## Constraints

- مسار الـpatch الإلزامي: `src/data/baselineGovernance.ts` فقط.
- يجب أن يحتوي الـpatch على `forecast_start_date` أو `forecast_end_date` فعليًا.
- لا تعديل قاعدة بيانات أو migrations أو بيانات اختبار من الوكيل المحلي.
