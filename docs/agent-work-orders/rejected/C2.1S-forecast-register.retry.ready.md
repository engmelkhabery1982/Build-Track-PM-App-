# بطاقة عمل محكومة — إعادة بعد تحسين حارس العمليات

## C2.1S — Forecast fields in the activity variance register

## الهدف التشغيلي

توفير سجل فروق نشاط يوضح Baseline وCurrent وCPM Forecast كمصادر مستقلة، دون
تغيير الخطة المعتمدة، بحيث يستطيع مدير المشروع التحقق من أثر التأخير على كل نشاط.

## مصدر الحقيقة والحدود غير القابلة للتعديل

- `BaselineActivitySnapshot` مجمد و`activity_code` هو الهوية المستقرة.
- Current هو حقول النشاط الحية وForecast هو `forecast_start_date`/
  `forecast_end_date` فقط؛ الغياب يبقى null/Unavailable.
- لا تحذف مقارنة `Critical` أو `predecessor_links` أو `stableJson`.

## معايير القبول

1. يضيف patch داخل `BaselineActivityVariance` حقول Forecast وتبايناتها عن
   Baseline، ويملؤها `compareBaselineActivityDetails` من حقول CPM فقط.
2. لا يعدل status أو changedFields الخاصين بمقارنة Baseline مع Current إلا
   لتسجيل تأخير Forecast موجود ومثبت.
3. يحتفظ بمنطق الميزانية والكمية والتقويم وCritical وpredecessor القائم.
4. يقترح اختبارًا لتوقع متأخر وآخر دون Forecast.
